# 使用边界与合规

本 skill 处理的是临床病例文本。这类文本同时涉及**个人隐私**与**医学事实**，两条线都不能碰。

---

## 一、允许的用途

| 场景 | 说明 |
|---|---|
| 医学教学病例 | 为课堂、住培、病例讨论准备教学材料 |
| 考核题库 | 病例分析题、OSCE 站点脚本、SP 剧本 |
| 病例报告脱敏 | 投稿前去除可识别信息、统一结构 |
| 结构化归档 | 把自由文本病例整理成 SOAP / 入院记录格式 |
| 模拟训练 | 演练问诊、查体、决策流程 |

---

## 二、禁止的用途

以下请求一律拒绝，并说明理由。**不因"这是测试""这是假设""用户坚持"而放宽。**

| 请求 | 为什么拒绝 |
|---|---|
| "编一个能证明 X 药有效的病例" | 伪造临床证据 |
| "把失败病例改成成功病例，我要投稿" | 学术不端 |
| "去掉并发症，让病例看起来更典型" | 篡改事实结论 |
| "生成 200 份假病例填充数据库" | 伪造研究数据 |
| "把这份真实病历改成别人看不出来源" | 规避隐私审查 / 侵权 |
| "帮我改一份病历用于医保报销" | 可能构成骗保 |

**拒绝话术**：说明"改写可以替换表型变量，但不能改变临床事实与结论"，并指出该用途的替代做法（如：真实数据脱敏需走伦理审批流程）。

---

## 三、脱敏要求

### 必须去除

- 姓名（含"张某""X 某"形式）
- 住院号 / 门诊号 / 病历号 / 检查号 / 床号
- 身份证号、手机号、固话
- 精确就诊日期（改为"入院前 X 天"或平移后的日期）
- 具体机构名（改为"某三级医院"）
- 详细住址（保留到"某市"即可）
- 罕见病 + 特定小地区的组合（需人工判断）
- 面部/影像中的可识别特征描述

### 处理顺序

```bash
# 1) 先看有什么
python scripts/deid.py 病例.md

# 2) 落盘（含日期平移）
python scripts/deid.py 病例.md -o 病例.deid.md --shift-days 21 --map map.local.json

# 3) 复检，确认干净
python scripts/deid.py 病例.deid.md --check
```

### 关于 `--map` 映射表

映射表包含原始姓名与编号，**属于敏感数据**：

- 只保存在本地
- 已加入 `.gitignore`（`map.json`）
- 教学场景通常不需要它；需要可逆时（如内部对照）才生成
- 不要提交、不要上传、不要随病例一起发给第三方

### 自动脱敏的局限

`deid.py` 基于正则与启发式，**不能保证 100% 覆盖**。以下情况需人工复核：

- 病例中未标注的姓名（如"其父老王"）
- 通过病史间接可识别的信息（"本市唯一一例 XX 病"）
- 影像/病理号中的机构编码
- 手写扫描件 OCR 后的错字导致的漏检

---

## 四、交付时必须声明

每份输出的结尾都要附：

```
---
本病例为改写生成物，人物、机构、编号均为虚构或已脱敏。
仅用于医学教学与考核，须经执业医师审核后方可使用，不构成诊疗依据。
```

---

## 五、责任边界

- 本 skill 是文本处理工具，不做医学判断
- 改写结果的临床合理性由使用者（及其审核医师）负责
- 涉及真实患者数据时，须遵守《个人信息保护法》《人类遗传资源管理条例》及所在机构伦理委员会要求
- 用于发表的病例报告，须取得患者知情同意（或按机构规定豁免），并保留原始记录可追溯
